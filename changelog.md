## split-main-module
Splits `app/main.py` (1384 lines) into modules. The split itself is behaviour-neutral; it also carries one bug fix, called out at the end.

- **Why:** `app/main.py` was the file four concurrent branches all edited, and where two of them reshaped overlapping regions git's three-way merge picked one side wholesale without reporting a conflict. That is exactly how #127's merge silently reverted #126's security middleware and `_sweep_sessions` (see `restore-lost-security-middleware` below) and it reproduced again on `publish-integrity`. Smaller files with one concern each shrink the window where that can happen quietly.
- **`main.py` is now assembly only** (~155 lines): the app object, middleware, `/healthz`, the three exception handlers, the router includes and the static mount. `app.main:app` is unchanged, so every entrypoint — `run.py`, the systemd unit, CI's import smoke test — is untouched.
- **New modules**, each owning one thing:
  - `config.py` — every setting read at startup: env vars, derived paths, the git-derived `APP_VERSION`/`ASSET_VERSION`, `_session_secret()`. One file to read to see the deployment knobs.
  - `sessions.py` — the server-side token store, `_user`/`_login`/`_require_login`/`_can_assign_others`, and the session sweep.
  - `workspace.py` — per-curator working copies end to end: adoption and the LRU bound, `service_for` (the write gate), branch state, the in-progress review session, dirty/touched markers, rollback, and the idle sweep with its archive.
  - `stores.py` — the two process-wide ledger singletons (`ASSIGNMENTS`, `ID_AUTHORS`), which more than one route module reads.
  - `routes/` — eight routers grouped by the page they serve: `ontology`, `review`, `feedback`, `auth`, `publish`, `settings`, `assignments`, `pages`.
- **Modules reference `module.NAME`, never a bare imported name**, for anything mutable. That is what keeps a setting patchable in one place and reaching the whole app; importing the value instead would freeze a private copy at import time.
- **The code moved verbatim.** Nothing was renamed and no logic was rewritten, so the diff reviews as a move rather than as a rewrite.
- **Rebased onto `fail-loudly`, `lint-and-frontend-tests` and `prune-derivable-columns`**, which merged while this was in progress. Everything those three changed in `app/main.py` was carried into the module that now owns it: the `NotFound`/`Invalid`/`ValueError` handlers and the dropped `KeyError` mapping into `main.py`, the sha in `APP_VERSION` into `config.py`, the reworded mapping note and the blockquoted curator comment into `routes/publish.py`. Lint is now a required gate, so the new modules are ruff-clean under `E,F,W,I` rather than carrying the old file's import order.
- **Tests now patch the module that owns the name** (`config.USER_DIR`, `sessions._login`, `workspace.USER_SVC`, …) rather than `main.*`. The merge-regression guard from #136 was repointed at the modules `main`'s lifespan now calls into, which is the new place a bad merge could break that wiring.
- **Editing or deleting a feedback entry that does not exist is a 404 again, not a 500.** `_own_feedback` raised a bare `KeyError`, which was correct while every `KeyError` mapped to a 404. `fail-loudly` removed that mapping deliberately — so an incidental dictionary bug 500s with a traceback instead of posing as a 404 — and took this genuine missing-entity case down with it. It now raises `NotFound`, as `feedback_service` already did for the same condition. Only the anonymous 401 path was covered, which is why nothing caught it; the signed-in PUT and DELETE against an unknown id are now tested, and were confirmed to fail without the fix.
- 234 tests pass (232 before, plus the two new ones). The route table was diffed before and after: the same 50 routes, exactly.
- Checked by mutation, not just by a green run — unregistering `security_headers`, removing the anonymous-write gate in `service_for`, and pointing the ref-session path away from `config.USER_DIR` each turned the suite red, confirming the tests still reach the code through the new module boundaries.

Verified against the running app: both pages render, a disease record loads over the greedy `{iri:path}` route, the review matrix builds all nine database columns, every security header is present on a live response, and the cache policy still marks HTML `no-cache`, a versioned asset `immutable` and an unversioned one `no-cache`.

The 39 now read the index's current name, and the 61 unresolvable edges are dropped from the files: 102,889 -> 102,828 edges, with the edge set otherwise identical and every surviving label non-empty and equal to its child's own index label. Resolving from the index makes this class of drift impossible rather than merely fixed.
- Verified by loading every index before and after through `predict_service.load_index`: `id`, `label` and `by_db` are identical for all 85,354 records. 206 tests pass, including three new ones pinning the own-id round trip through the real reader, the label-free edge format, and `load_subtypes` resolving names from the indexes.

## restore-lost-security-middleware
Fixes a regression introduced on `main` by the merge of #127.

- **`main` was red and the background sweep task was broken.** Merging #127 (`data-durability`) resolved `app/main.py` by taking the branch's side of two regions that #126 had just added, silently dropping:
  - `_sweep_sessions()` — while **leaving its call site** in `_sweep_loop()`. The task raises `NameError` on its first tick, six hours after a deploy, inside a coroutine nobody is watching. Sessions therefore never expire, which was the whole point of #110.
  - the `security_headers` middleware — so every response lost its CSP, `X-Frame-Options`, `X-Content-Type-Options` and `Referrer-Policy`. The page was framable again and the SRI pinning had no policy behind it.
- Neither side of that merge conflicted textually, so git reported "Automatic merge went well" and nothing asked for a human. Both are restored verbatim from the merged `security-hardening` branch.
- **Two guards so a merge cannot do this again quietly.** `test_the_sweep_loop_only_calls_functions_that_exist` asserts the wiring rather than the behaviour — the part a bad three-way merge breaks — and `test_the_security_middleware_is_registered` names the cause, so a failure points straight at it instead of only showing a missing header. Both were checked by removing the code and confirming they fail.
- 188 tests pass.

## deployment
Closes #122. Stacked on `security-hardening` (shares `deploy/nginx.conf`).

- **The deploy no longer restarts out from under a curator.** `update.sh` ran `git reset --hard` and restarted on a ten-minute timer whenever the branch moved, with no gate. It now asks `/healthz` first and defers the restart when any curator's working copy is live in memory, so an idle window is found within ten minutes instead of the deploy interrupting someone mid-edit. `ARI_FORCE_RESTART=1` overrides for an urgent fix. (The data loss this used to cause is fixed separately in `data-durability`.)
- **`GET /healthz`** returns ontology load state, working-copy count, in-memory worlds, session count and version — 503 when the base ontology will not load. No session required and no curation content in the response. nginx has a location block for it with `access_log off`.
- **The cache-busting scheme finally does something.** Real care went into `__ASSETV__` — one git-derived token, substituted at render, tagging every asset so a deploy busts all of them at once. Then `no_cache_assets` set `Cache-Control: no-cache` on **every** `.js` and `.css` response, so nothing was cached and the token did nothing: every page load re-downloaded all thirteen JS files and the stylesheets, which is the slowest part of opening a record on the laptops this audience uses. HTML still revalidates (it carries the token); an asset *requested with* a version token is immutable by construction and now gets `max-age=31536000, immutable`.
- **The three CDN libraries are vendored.** SRI pinning is exactly right for integrity but does nothing for *availability*, and hospital, university and pharmaceutical networks block third-party CDNs routinely — the failure mode was a broken pathophysiology graph and word cloud with nothing on screen explaining why. `static/vendor/` holds chart.js 4.5.1, d3 7.9.0 and d3-cloud 1.2.7, **each verified byte-for-byte against the SHA-384 the page already pinned**, so what is committed is exactly what was being served. `static/vendor/README.md` records the versions, upstream URLs and how to check a digest before refreshing one.
- That removes the CDN exception from the CSP: `script-src` is now `'self'` alone.
- Fonts still come from Google Fonts. They degrade to the fallback stack rather than breaking a feature, so vendoring them is lower value and larger; the CSP still allows those two origins.

Verified against the running app: all three libraries load from `static/vendor/` with no CDN request and no console errors, `/healthz` returns 200 with the ontology loaded, a versioned asset gets the immutable header and an unversioned one does not, and the record page renders unchanged.

## security-hardening
Closes #102, #106, #110, #113.

- **The feedback API is no longer open to the world.** All four `/api/v2/feedback` routes required no session and took `author` straight from the request body, so anyone could post a comment under a named curator's identity and delete any curator's feedback. Writes now require a session, the author comes from `_login(request)` and is never read from the payload, and editing or deleting an entry is restricted to its own author (or an `ASSIGN_ADMINS` administrator). Messages are capped at 4,000 characters, and a delete that matches nothing no longer rewrites the whole file.
- The feedback panel drops its free-text "Your name" box — it now says *Posting as `<login>`*, offers a sign-in prompt when signed out, and shows Edit/Delete only on your own comments, matching what the server enforces.
- **Sign-in asks for `public_repo` instead of `repo`.** `repo` is read and write over every repository the curator can reach, including their employer's private ones; the app forks one public repository and pushes one branch. `public_repo` is the narrowest scope that still covers fork + commit + pull request.
- **Sessions expire.** Entries carry a `created` stamp and are swept after `SESSION_TTL_DAYS` (default 30) by the loop that already sweeps working copies. The store previously only ever shed an entry on an explicit logout, so it grew into a file of long-lived GitHub tokens for everyone who had ever signed in.
- `.sessions.json` is created at `0600` via `os.open` and moved into place with `os.replace`, rather than being written and then chmod-ed — between those two statements the file carried the process umask.
- **`SESSION_SECRET` is required wherever GitHub sign-in is configured**; the app refuses to start without it rather than generating a per-process key that signs every curator out on each of the ten-minute deploy restarts. `_load_dotenv` also strips matching surrounding quotes, so `SESSION_SECRET="abc"` no longer loads the quotes as part of the key.
- **Security headers on every response** — `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, and a CSP with `frame-ancestors 'none'` that finally puts a policy behind the existing SRI pinning. Set in the app so a local or non-nginx run is covered too; `deploy/nginx.conf` adds HSTS and repeats the rest with `always`.
- **Rate limiting in nginx**: 20r/s on the API with a burst of 40, and 6r/m on `/api/v2/publish`, which fans out to eight GitHub calls.
- **The open-redirect gap is closed.** `_safe_next()` matched on the `/` prefix, so `/\evil.com` — which browsers normalise to a protocol-relative URL — passed and left the site. It now parses with `urlsplit` and requires an empty scheme and netloc.
- **Three endpoints gained the gate their docstrings assumed.** `POST /api/v2/releases` is now restricted to `ASSIGN_ADMINS` (cutting a release also archives all non-kept feedback) and takes its editor from the session; `GET /api/v2/id-authors` requires a session, being the evidence base for separation of duties; and a sign-in with `ALLOWED_LOGINS` unset is logged at WARNING.
- `_require_login()` raises 401 rather than a `ValueError` the global handler turned into a 400 — "you are not signed in" and "your request was malformed" are different things and the client shows different affordances for them.
- 24 new tests across `tests/test_feedback_auth.py` and `tests/test_security_boundaries.py`; 173 pass.
## main-branch-object-pruning
- **The reference indexes lost 2.4 MB (17%) of redundant bytes without changing a single match.** `data/2-databases/*.index.tsv` went from 13.88 MB to 11.52 MB — NCIt 4.73 → 3.10, MONDO 5.09 → 4.56, Orphanet 1.45 → 1.35, DOID 1.47 → 1.42, MeSH 1.14 → 1.09. `write_index` in `scripts/fetch_databases.py` now applies two rules, and the committed files were re-emitted under them; no reader was touched.
- **Synonyms that only echo the label are dropped** (51,316 of them, 40,391 in NCIt alone, which repeats a term's own name as its first synonym on nearly every row). Both `predict_service.LexicalIndex.add` and `enrich_service` walk `[label] + synonyms` and keep the first spelling of each key, so an echo could never match anything the label did not already match — it was only a duplicate chip in the compare pane. The comparison is casefold-only, deliberately weaker than `normalize()`, so punctuation and accent variants ("Sjögren" vs "Sjogren") survive as the distinct names they are.
- **Columns a source never fills are no longer written.** Each source populates only a few of the ten target columns — MeSH one, NCIt two — and `omop` is empty in all five, there being no freely redistributable OMOP source. An always-empty column was a tab per row and nothing else. `predict_service` reads columns by name, so an absent column reads as "this source cross-references nothing there".
- **The `omim` column is gone**, finishing what `remove-omim-mappings-ref-edits` started: it left the column in place because the loader ignores it, and noted a future rebuild would stop writing it. `parse_obo` still harvests OMIM, so restoring the column is a `review: True` flip plus a rebuild.
- **Two further prunes were measured and rejected because they need reader changes.** Dropping `child_label` from `*.subtypes.tsv` would save 3.66 MB but `enrich_service.load_subtypes` reads that column directly; dropping each index's self-id column (`mondo` in `mondo.index.tsv`) would save 0.54 MB but it is the sole source of that database's own prediction, via `by_db`.
- Verified by loading every index before and after through the real reader (`predict_service.load_index`): the match-key space (84,145 MONDO / 66,047 NCIt / 31,190 DOID / 26,896 Orphanet / 35,671 MeSH), the records each key resolves to, and every record's `id`, `label` and `by_db` are identical in all five. Only the synonym display lists shrank, by exactly the echo count. 148 tests pass, plus two new ones pinning the writer rules.
## fail-loudly
Closes #115, #123. Stacked on `publish-integrity`.

- **A value that cannot be stored is now reported.** `update_disease()` skipped any key not in `EDITABLE` and swallowed numeric conversion failures, so a curator typing "about 30 per 100k" into a numeric prevalence field got a successful save, a changelog entry, and no value stored — a data-entry trap for exactly the audience this tool is for. Rejections come back on the detail as `rejected: [{field, value, reason}]`, and the form reports them instead of "Saved". **[UI change — needs review]**
- **The changelog no longer silently no-ops.** `_append_changelog()` looked up `ARI_ChangeLog` and returned without writing (and without logging) when it was absent, so on any ontology where that annotation property had not been declared every edit was recorded nowhere while the caller still reported success. It uses `_ensure_annotation_property()`, as the other writers do.
- **Bugs no longer masquerade as client errors.** Every `KeyError` was mapped to a 404 and every `ValueError` to a 400, with the exception's message as the client-visible detail — so an incidental `KeyError` from a dictionary bug anywhere in the request path became a "not found" carrying an internal key name, and never produced a stack trace. `app/errors.py` adds explicit `NotFound` and `Invalid` types, the seven deliberate raises use them, and a bare `KeyError` now 500s with a logged traceback. `NotFound` subclasses `KeyError` so the service layer's own `except KeyError` blocks are unaffected, and overrides `__str__` because `KeyError` quotes its argument.
- **The PR body reads as a sentence.** It rendered as *"3 new 5 positive / 2 negative / 1 no-term-found judgment(s) added to…"* — the new-row count and the verdict counts concatenated with no connecting words, in every review PR. It now reads *"5 confirmed, 2 flagged — 3 new row(s) added to…"*.
- **The curator comment is quoted, not interpolated.** It went into the assembled markdown raw, so markdown and HTML in a comment rendered in a public artefact.
- **The version string carries the sha the README documents.** `_app_version()` produced `2.<count> (<date>)` while `README.md` documents `2.<count> (<sha>, <date>)` — and the sha is the useful half in a bug report.
- **Predictions are cached per ontology mtime.** The index files were already cached with an mtime signature, but `predict_xrefs()` rebuilt the disease list and re-ran the whole matching pass on every call, and the review page calls it on every load.
- A comment in `_merge_tsv` records that rewriting and re-uploading the whole mapping file on every publish is known and bounded, so the eventual move to append-only is deliberate rather than a discovery.
- `USER_TOUCHED` clearing (#123 item 2) and the `added` count no longer being `max(n1, n2)` (item 1, second half) landed in `publish-integrity` and `mapping-correctness` respectively.
- 10 new tests in `tests/test_fail_loudly.py`; 186 pass.

## publish-integrity
Closes #111, #112. Builds on `data-durability` (uses its atomic-write helper).

- **A failed publish no longer leaves its changes applied.** `log_xref_review()` and `apply_enrichment()` both write to the working copy *before* the eight GitHub calls that publish it, so any failure among them left the changelog entries and the enrichment in place — the curator saw "Publish failed", clicked again, and both were applied a second time. The working copy is snapshotted first and rolled back on failure.
- **A retry is no longer a second commit.** If the commit and PR succeed but the response is lost — a proxy timeout, a closed laptop, a flaky connection — the curator republished and a second commit landed carrying the same judgments, with nothing on either side detecting the repeat. The client now sends a `request_id` per publish *attempt* and keeps it across a failure, and the server returns the first result for a repeat instead of committing again. The last 20 attempts per curator are remembered.
- **`USER_TOUCHED` is cleared on a successful publish.** It accumulated every disease IRI a curator edited for the life of the process and scoped the change summary in every subsequent PR body, so the second and later PRs of a session described changes that had already been published.
- **A reused branch catches up with the base before committing.** `base_sha` was only ever used to *create* a branch, so a reused one was built on its own tip however far upstream had moved, and a long review session produced a PR whose diff carried unrelated drift. The base is now merged in first; a conflict refuses with a sentence rather than guessing at someone's ontology merge.
- **A merged or closed PR is no longer tracked as if it were open.** The lookup filtered `state: open`, so a tracked PR that had been merged was invisible, a *new* PR was opened, and the client went on pointing at the old number — the curator could not tell which of the two their work went into. The response now carries `superseded`, and the review page says "PR #N was merged, so this went into a new submission, PR #M." **[UI change — needs review]**
- **Fork detection checks the parent, not just the name.** A 200 from `GET /repos/{login}/{repo}` was taken as "the user's fork exists", so a curator who happened to own an unrelated repository of the same name got their branch and commits pushed into it. `_is_fork_of()` now requires `fork == true` and a matching `parent.full_name`, and says plainly what to do when the name is taken by something else.
- **Idempotent reads retry with exponential backoff**, honouring `Retry-After`, for the statuses a retry can actually clear (403/429/5xx).
- **GitHub failures are translated into sentences a curator can act on.** A secondary rate limit surfaced as `Publish failed: You have exceeded a secondary rate limit` in an `alert()`, with no retry and no guidance. `github_service.explain()` now maps the common failures to plain sentences, each of which says the curator's work is saved. **[UI change — needs review]**
- The 30-second first-publish fork wait is logged so an operator can see what the silent pause is. Surfacing it to the curator in the button label is part of the onboarding work in #119.
- 15 new tests in `tests/test_publish_integrity.py`; 176 pass.

## data-durability
Closes #103, #104, #107, #108, #120.

- **A restart no longer discards and then overwrites a curator's unpublished work.** `USER_SVC` was in-memory only and nothing rehydrated it, so after the ten-minute deploy restart a signed-in curator's reads fell through to `BASE` — their edits looked gone — and their next write took the `create=True` branch and copied the pristine base straight over their working copy. `user_service()` now adopts an existing `.user-data/<login>.owl` on both the read and the write path, and only copies the base when there is genuinely no file.
- A new working copy is stamped with the current time: `shutil.copy2` preserves the *base file's* mtime, and the idle sweep reads mtime as "last touched", so a fresh copy looked two weeks idle from birth.
- **Idle working copies with unpublished changes are archived, never deleted.** The sweep checked mtime alone, so a curator on two weeks' leave came back to find an afternoon of curation gone. It now compares the copy against the published base — `USER_DIRTY` alone is not enough, since a restart clears it — and moves anything unpublished into `.user-data/archive/<login>.<timestamp>.owl` with a WARNING. A copy byte-identical to the base carries nothing and is still removed. `GET /api/v2/settings` now reports `working_copy: {days_left, ttl_days, unpublished}` so the UI can warn while the copy is still recoverable.
- **In-memory ontology worlds are bounded.** `USER_SVC` is an LRU `OrderedDict` capped at `MAX_LOADED_WORLDS` (default 8). Each entry is a full owlready2 `World` over a ~1.7MB file and nothing evicted them, so memory grew with every distinct curator until a restart. The working copies are durable files, so eviction only costs a reload.
- **ARI numbers come from one server-side counter.** `_next_ari_number()` scanned for the highest number and returned max + 1 — but each curator scans their own private working copy, so two curators creating a disease the same afternoon both minted the same number, and the colliding IRI made RDF fuse two unrelated diseases into one individual once both PRs merged. `app/id_allocator.py` allocates under a lock from `provenance/ari-id-counter.json`, keeps an audit trail of who took which number, and can only ever move forward — a stale working copy cannot reissue a number a merged PR already took. `_highest_ari_number()` is the non-consuming peek.
- **Switching source branch is per-curator and no longer overwrites the shared ontology.** `STATE` was a process global that any signed-in curator could change via `POST /api/v2/source`, and `_fetch_branch()` wrote the downloaded bytes over the git-tracked `ontologies/ari_t1d.owl`. So one curator exploring a colleague's `edit/*` branch changed what every other curator and every anonymous reader saw, left everyone else diffing their publish against a swapped baseline, and made `deploy/update.sh` find a dirty tree and autostash every ten minutes forever. Branch choice now lives in `.user-data/<login>.branch.json` and a fetch lands in that curator's own working copy.
- **Every write goes through one atomic helper.** `app/atomic_store.py` serialises to a temp file in the destination's own directory, fsyncs, and `os.replace()`s it into place — covering the ontology (~1.7MB of RDF/XML written on *every* field edit, item edit, review log and enrichment, previously in place with no backup and no previous version) and the session, provenance, assignment, feedback and ref-session stores.

## mapping-correctness
Closes #105, #116.

- **A corrected mapping judgment is no longer silently discarded.** `load_judgments()` keyed its `seen` set on `(ari_id, prefix, id)` and kept whichever row came *first* in the file — which is append order, so the older judgment always won. A curator confirmed a mapping, someone later flagged it as wrong, and the review page went on showing it as confirmed forever; a flagged id looked unjudged to the next person, who might confirm it again. The projection to current state now ranks rows on (not superseded, `mapping_date`, file position) and the most recent judgment wins.
- **A withdrawn row is marked, not merely outvoted.** `_merge_tsv` appended any row with a new dedup key and marked nothing, so the published set asserted that the same pair both is and is not an exact match with no ordering and no retraction predicate — a downstream consumer could not resolve it either. `_reconcile_judgments()` now writes a `Superseded by the <verdict> judgment of <author> on <date>.` note into the row a reversal replaces, using SSSOM's standard `comment` slot so the file still validates.
- That also fixes a case the dedup key could not express at all: **re-confirming a mapping after it was flagged** was dropped entirely, because a row with that key already existed, so the flag kept winning no matter how many times the judgment was reversed back. Fixing the stored text is a data change for a curator, deliberately not bundled into this fix — `mdToHtml` already renders markdown, so `**bold**`, `*italic*` and `[text](https://…)` are the supported way to express this.
- Verified no double-escaping at the call sites: the five `esc()` calls that wrap link helpers (`xrefLink`, `diseaseLinkUrl`, `sub.link_iri`) pass plain URLs into `href`, where `&amp;` correctly decodes back to `&` — confirmed against a live SNOMED browser link carrying two query parameters. ## fix-git-permanently-dirty-worktree
- Fixed the repo permanently reporting `static/ref-edits/ref-edits.js` as modified with no edits made. The file was committed with CRLF line endings, but Git for Windows sets `core.autocrlf=true` (system gitconfig), so Git normalised the working copy back to LF on every index refresh and the result never matched the committed blob — `git checkout --` restored CRLF and the file went dirty again immediately.
- Renormalised that one file to LF (`git add --renormalize`); content is byte-identical ignoring line endings, and it is now the same LF-in-index / CRLF-in-worktree shape as every other text file here, so `git status` stays clean. ## feat-concept-detail
- Added `GET /api/v2/concept/{db}/{id}` — label, exact synonyms, definition and parent terms for one target-database id, so the reference-review compare pane can show the candidate concept next to the ARI disease instead of just its label. The pane (in the ref-edits side panel) mirrors the two as columns and highlights the strings they share, folded the same way `predict_service` folds names so the highlighting agrees with the matcher.
- Every field is attributed to the index it came from. Only MONDO, DOID, NCIt, MeSH and Orphanet have an index of their own; SNOMED, OMOP, ICD-10, OMIM and UMLS appear only as cross-reference columns on those. So a lookup of a SNOMED/OMOP/… id returns `direct: false` with a `via` list of the hub term(s) that cross-reference it and a plain-language `note`; the pane labels that column "via MONDO" (etc.), never as the target database's own term. When several hubs claim one id their labels are all returned, and a disagreement is flagged for the curator. A valid-but-unindexed id is a normal `found: false` 200, not a 404.
- Definitions and parent terms are stored in a **sidecar** `<db>.details.tsv` (id → definition, parents) next to each index, not in the index itself: folding them in would roughly double the index size (measured 13.9 MB → 32.2 MB) and slow every prediction load for data prediction never uses. `concept_service` loads the sidecars lazily and caches them; the prediction hot path (`<db>.index.tsv`) is byte-identical to before. A missing sidecar reports `details_available: false` with a note (a checkout that never regenerated still answers with label + synonyms + provenance); a missing id within a present sidecar means the term genuinely has none. `scripts/fetch_databases.py` now also writes the sidecars, capturing OBO `def:`/`is_a:` (parents resolved to labels in a second pass, OBO qualifiers stripped), MeSH scope notes, and Orphanet definitions.
- Regenerated and committed the five detail sidecars (~18 MB total, loaded on demand); the prediction indexes are unchanged. Prediction behaviour, confidence rules and SSSOM output are unchanged — proved by a snapshot test over `predict_matches` (adding a sidecar does not alter predictions).
- Kept the lookup's memory cost proportional to use, for the small hosted instance (see `DEPLOY.md`): only the sidecar of the database actually being looked up is read (a DOID lookup holds ~8 MB resident, not the ~52 MB all five would), and the reverse id-index stores `(source, record)` tuples rather than a dict per entry (~49 MB instead of ~77 MB). Together that trims the lookup from ~129 MB to ~57 MB, all of it lazy — nothing loads until a curator opens the compare pane, so app startup is unaffected.
